# Deep Code-Level Analysis of NourmehrWebsite-jszip

## 1. Overview
This document provides a **code‑level trace** of the API surface, the **data flow** from the Vue frontend to the Express backend, and a **mapping** between Pinia stores and backend controllers. It focuses on the core user‑facing features (authentication, product catalog, and shopping cart) and shows how the router, services, and stores interact with the backend.

## 3. Frontend API Service (`src/services/api.js`)
* Base URL: `import.meta.env.VITE_API_BASE_URL || '/api'`
* Request interceptor adds `Authorization: Bearer <token>` when a valid `auth_token` exists in `localStorage`.
* Response interceptor clears the token and redirects to `/login` on a 401 response.

All Pinia stores use this `api` instance for HTTP calls, ensuring a single place for auth handling.

---

## 4. Authentication Flow (Auth Store ↔ Auth API ↔ Auth Controller)
1. **Login** (`src/stores/auth.js` → `api.post('/auth/login')`)
   - Calls `backend/routes/authRoutes.js` → `POST /login` → `authController.login`.
   - Controller verifies credentials, updates `lastLogin`, generates a JWT via `generateToken`, and returns `{ token, user }`.
   - Store saves token & user to Pinia state and `localStorage`/`sessionStorage`.
2. **Register** (`api.post('/auth/register')`) → `authController.register` → creates a new `User` document and returns a token.
3. **Session Validation** (`auth.getMe` via `api.get('/auth/me')`)
   - Protected route (`protect` middleware) returns `req.user` populated by the JWT.
   - Store loads the user into state on app start (`loadFromStorage`).
4. **Logout** (`api.post('/auth/logout')`) → `authController.logout` clears the cookie on the server; the store clears local storage.
5. **SMS Verification** (`requestSmsCode` / `verifySmsCode`)
   - Calls `/auth/sms/request` and `/auth/sms/verify` which map to `requestSmsCode` and `verifySmsCode` in the controller.
   - Supports a mock flow when `SMS_PROVIDER` is not configured.

## 5. Product Flow (Product Store ↔ Product API ↔ Product Controller)
* **Fetching a list** – `useProductStore.fetchProducts(params)` → `api.get('/products?...')`
  - Backend: `productRoutes GET /` → `productController.getProducts`.
  - Controller applies filters (`category`, `search`), pagination, sorting, and calculates `finalPrice` (discount handling).
  - Returns `{ success, data: products, total }` which the store writes to `products` and `pagination`.
* **Fetching a single product** – `fetchProduct(idOrSlug)` → `api.get('/products/:id')`
  - Backend: `productRoutes GET '/:id'` → `productController.getProductBySlugOrId`.
  - Increments `viewsCount`, adds `finalPrice` and formatted price fields.
* **Fetching categories** – `fetchCategories()` → `api.get('/products/categories')`
  - Backend: `productRoutes GET '/categories'` → `productController.getCategories`.

---

## 6. Cart Flow (Cart Store ↔ Cart API ↔ Cart Controller)
1. **Load Cart** – `useCart.fetchCart()` → `api.get('/cart')`
   - Backend: `cartRoutes GET /` (protected) → `cartController.getCart`.
   - Controller populates cart items, calculates `subtotal`, adds a flat `shippingCost` (80000 if subtotal > 0), and returns the full cart payload.
2. **Add Item** – `addToCart(productId, qty, color)` → `api.post('/cart/add')`
   - Backend: `cartRoutes POST /add` → `cartController.addToCart`.
   - Checks product existence, stock, merges with existing cart item, saves, and returns success.
3. **Update Quantity** – `updateQuantity(productId, qty, color)`
   - Finds the cart item ID via a temporary `GET /cart`, then `PUT /cart/item/:itemId` → `cartController.updateCartItem`.
   - Validates stock before updating.
4. **Remove Item** – `removeFromCart(productId, color)` → `DELETE /cart/item/:itemId` → `cartController.removeCartItem`.
5. **Clear Cart** – `clearCart()` → `DELETE /cart/clear` → `cartController.clearCart` (deletes the cart document).

```

```

## 9. Observations & Recommendations
* **Consistent Token Handling** – The frontend stores the JWT in `localStorage` and also reads it from a cookie (`router.js`). Consider consolidating to a single source to avoid mismatches.
* **Error Propagation** – Controllers return `{ success: false, message }` which the stores surface via `error` refs. Ensure UI components display these messages uniformly.
* **Shipping Cost Logic** – Currently a flat `80000` is applied in `cartController.getCart`. If business rules change, move this logic to a dedicated service.
* **Admin Routes** – Not covered in this analysis, but they follow the same pattern (router → admin controller). Ensure admin middleware validates `user.role === 'admin'`.
* **Unit Tests** – Adding tests for each controller (especially auth & cart) will safeguard the data‑flow contracts.
